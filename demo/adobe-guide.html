Connecting Your Firm's Adobe Account — Law 4 Warriors

One page. Five minutes. You do this once, when the system is delivered.

The Law 4 Warriors system uses Adobe Acrobat Services (PDF Extract) to read VA rating decision letters and pull the ratings, dates, and deadlines into each client's master record automatically. The system ships with no Adobe account attached. You connect your firm's own account — here's why, and how.

Why the Adobe account must be the firm's

  • Billing. Usage is billed to the account holder. At this firm's volume the free tier (below) should cover you for the foreseeable future — but if that ever changes, the bill should be the firm's, in the firm's name.
  • Audit trail. Every Adobe API call is logged against your account. When Adobe's logs — or opposing counsel, or the VA — ask whose credentials processed a veteran's decision letter, the answer should be "the firm's," never a vendor's personal account.
  • Terms. Adobe's developer terms tie API credentials to the account holder. Running client documents through someone else's account puts the firm outside those terms.
  • Control. Your credentials, your off-switch. You can revoke access the moment you choose (see "Revoke or rotate" below) without asking anyone.

Step-by-step: create the credentials (Adobe Developer Console)

  1. Adobe ID. If the firm doesn't have one, create an Adobe ID at adobe.com using a firm-controlled email address (not a personal one). Sign in with it.
  2. Open the Developer Console. Go to developer.adobe.com/console.
  3. Create a project. Click Create new project. Name it Law 4 Warriors (the name is for your eyes only).
  4. Add the API. In the project, click Add API. Choose Adobe Acrobat Services and click Next. (This one API includes PDF Extract, which is what the system uses.)
  5. Create the credential. When asked for a credential type, choose OAuth Server-to-Server, give it a name (e.g. L4W backend), and click Save configured API.
  6. Copy the two values. Adobe now displays a Client ID and a Client Secret. Copy both — treat the secret like a password. (If you ever lose it, you can generate a fresh one; see below.)

Paste them into the system

Open the Connect Adobe setup screen in the Law 4 Warriors admin (the connect-adobe.html page delivered with the backend), paste the Client ID and Client Secret into Step 2, and click Save credentials. They are stored encrypted (Fernet encryption) in a vault file on your server. The secret is never shown on screen again.

Command-line alternative: python adobe_connect.py set, then follow the prompts. Check state any time with python adobe_connect.py status.

Test the connection

On the Connect Adobe screen, click Test connection (or run python adobe_connect.py test). The system performs a real sign-in against Adobe's login service with your credentials:

Result Meaning
Connected Adobe issued an access token. You're live. Tokens last 24 hours; the system refreshes them automatically — nothing for you to renew by hand.
Authentication failed Adobe rejected the credentials: a typo, a secret that was regenerated, or a credential from a project without the Acrobat Services API. Re-copy from the Console and test again.
Configured — untested Credentials are saved but no test has run yet. Click Test.

What the free tier covers — and when you'd pay

  • The Acrobat Services free tier includes 500 document transactions per month at no cost and requires no credit card. Processing one decision letter is a small number of transactions.
  • The firm opens roughly 4–5 new cases a month. Even with re-processing, appeals, and testing, expect to use a small fraction of the free tier.
  • You would only need a paid plan if the firm's volume grows far beyond that, or if Adobe changes its free-tier terms. Paid plans are per-transaction volume agreements arranged with Adobe — set one up only if the system reports you're approaching the limit.
  • Acrobat Sign (Stage 2 — e-signature on the 21-22a, fee agreement, and releases) is a separate Adobe product with its own subscription; it connects the same way when that stage is delivered.

Revoke or rotate the credentials

  • Rotate (routine hygiene, or staff change): in the Developer Console, open the project → the OAuth credential → generate a new Client Secret (or add a second credential and delete the old one). Paste the new secret into Connect Adobe and click Test connection. The old secret stops working the moment you delete it in the Console.
  • Revoke completely: delete the credential (or the whole project) in the Developer Console. Adobe access ends immediately, everywhere.
  • Disconnect this system only: run python adobe_connect.py clear (or the admin tool's Clear credentials). The vault forgets the credentials; the Adobe-side credential technically still exists, so revoke it in the Console too if you want a clean cut.

Where your credentials live

They never leave your server. The Client ID and Secret sit encrypted in adobe-vault.json on the machine that runs the backend, unlocked by a vault key stored on that same machine. The only place they are ever sent is Adobe's own login endpoint (ims-na1.adobelogin.com) — which is the entire point of them. They are not in the website, not in GitHub, not in any document, and were never in the system as delivered: it arrived with an empty vault, waiting for yours.
